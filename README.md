# Multilayer Perceptron (MLP) from Scratch

A neural network implemented entirely from scratch using only NumPy (no TensorFlow/PyTorch). Built to classify breast tumors as **Malignant (M)** or **Benign (B)** using the Wisconsin Breast Cancer Dataset (569 samples, 30 features).

## Project Structure

```
multilayer_perceptron/
├── main.py              # CLI entry point for training
├── predict.py           # CLI entry point for inference
├── compare_models.py    # Adam vs SGD training comparison
├── split.py             # Train/validation splitter
├── model.py             # Training loop, early stopping, standardization, serialization
├── network.py           # Forward & backward propagation
├── optimizer.py         # SGD and Adam optimizers
├── utils.py             # sigmoid, ReLU, softmax, cross-entropy, one-hot, metrics
├── run_train_model.sh   # Convenience script: split → train → predict in one step
├── data.csv             # Raw Wisconsin Breast Cancer dataset
├── train.csv            # 80% split (generated by split.py)
├── validation.csv       # 20% split (generated by split.py)
├── model.npz            # Serialized trained model (NumPy archive)
├── learning_curve.png   # Loss / accuracy plot (generated)
├── optimizer_histories.json # Adam/SGD training histories (generated)
└── optimizer_comparison.png # Adam/SGD comparison plot (generated)
```

## How It Works

1. **Data split** ([split.py](split.py)): Shuffles `data.csv` with a fixed seed and writes `train.csv` (80%) and `validation.csv` (20%).
2. **Data loading** ([main.py](main.py)): Reads the CSVs, extracts 30 numeric features (columns 2+), and one-hot encodes the label (`M` → `[0, 1]`, `B` → `[1, 0]`).
3. **Standardization** ([model.py](model.py)): Z-score normalization applied inside `Model.fit()`. Training mean/std are stored on the model and reused at inference to prevent data leakage.
4. **Network construction** ([network.py](network.py)): Builds a fully-connected network with configurable hidden layers (default: 3 layers of 24 neurons). Weights are initialized with **He Uniform** (default) or **Xavier Uniform**.
5. **Forward pass**: Hidden layers use a configurable activation (ReLU or sigmoid); the output layer uses **softmax**.
6. **Backward pass**: For cross-entropy + softmax the gradient simplifies to `(y_pred - y_true) / batch_size`.
7. **Optimization** ([optimizer.py](optimizer.py)): **SGD** (vanilla gradient descent) or **Adam** (adaptive moment estimation with bias correction).
8. **Training** ([model.py](model.py)): Mini-batch training with shuffling, tracks loss/accuracy for train and val, and **early stopping** (restores best weights after patience runs out).
9. **Output**: Saves `model.npz` (NumPy archive) and a `learning_curve.png` plot.
10. **Optimizer comparison** ([compare_models.py](compare_models.py)): Trains Adam and SGD from the same random seed, then saves their validation histories and comparison curves.

## SGD vs Adam

Both optimizers minimize the same loss. Adam keeps per-parameter running averages of the gradient (1st moment) and its square (2nd moment) with bias correction. SGD applies a single global learning rate to every parameter.

| Optimizer | Update rule |
|---|---|
| **SGD** | `W ← W − lr · ∇W` |
| **Adam** | `m ← β₁m + (1−β₁)∇W` · `v ← β₂v + (1−β₂)(∇W)²` · `W ← W − lr · m̂ / (√v̂ + ε)` |

**Practical takeaway**: Default to Adam when you cannot afford a learning-rate sweep — it adapts per-parameter step sizes from gradient history. SGD needs careful LR tuning; with the right rate it can match Adam, but finding that rate has a real cost.

## Design Decisions

**Why softmax + cross-entropy only?** The combined derivative simplifies to `(y_pred − y_true)`, which is numerically stable and cheap. Unsupported combinations raise an error immediately.

**Why ReLU as the default hidden activation?** Modern default for deep networks. Sigmoid can be competitive on small datasets but ReLU is the safer general choice. Both are supported via `--activation`.

**Why separate `Model` and `Network`?** `Model` owns the training loop, standardization, and serialization. `Network` owns forward and backward only — keeping responsibilities focused and independently testable.

**Why `model.npz` over pickle?** NumPy's `.npz` format is cross-platform, version-stable, and does not execute arbitrary code on load (`allow_pickle=False` is enforced).

## Usage

### Quick start (one command)

```bash
bash run_train_model.sh [adam|sgd]
```

Runs split → train → predict in sequence. Defaults to `adam`.

### Step by step

#### 1. Split the dataset

```bash
python split.py data.csv --ratio 0.8 --seed 42
```

Produces `train.csv` and `validation.csv`.

`--ratio` must be strictly between `0` and `1`; invalid values raise a `ValueError`. Set `--seed -1` to split without explicitly seeding Python's random generator.

#### 2. Train

```bash
python main.py --data train.csv --val_data validation.csv \
  --layers 24 24 24 --epochs 200 --batch_size 4 \
  --learning_rate 0.0001 --solver adam --activation relu \
  --weights_initializer heUniform --seed 42
```

| Argument | Description | Default |
|---|---|---|
| `--data` | Training CSV | `train.csv` |
| `--val_data` | Validation CSV | `validation.csv` |
| `--layers` | Hidden layer sizes (min 2) | `24 24 24` |
| `--epochs` | Training epochs | `200` |
| `--batch_size` | Batch size | `4` |
| `--learning_rate` | Learning rate | `0.0001` |
| `--solver` | `adam` or `sgd` | `adam` |
| `--activation` | `relu` or `sigmoid` | `relu` |
| `--weights_initializer` | `heUniform` or `xavierUniform` | `heUniform` |
| `--seed` | Random seed | `42` |

Outputs: `model.npz` and `learning_curve.png`.

#### 3. Predict

```bash
python predict.py --data validation.csv --model model.npz
```

| Argument | Description | Default |
|---|---|---|
| `--data` | Input CSV | `validation.csv` |
| `--model` | Trained model file | `model.npz` |

Prints loss, accuracy, precision, recall, F1, specificity, and confusion matrix for the Malignant class.

#### 4. Compare Adam and SGD

After creating `train.csv` and `validation.csv`, run:

```bash
python compare_models.py
```

The comparison uses the same `[24, 24, 24]` architecture, learning rate (`0.001`), batch size (`32`), and random seed (`42`) for both optimizers. Adam trains for up to 100 epochs and SGD for up to 200 epochs; both use early stopping with a patience of 5 epochs and `min_delta=0.001`.

Outputs:

- `optimizer_histories.json`: training and validation loss/accuracy histories for both optimizers
- `optimizer_comparison.png`: side-by-side validation loss and validation accuracy curves
